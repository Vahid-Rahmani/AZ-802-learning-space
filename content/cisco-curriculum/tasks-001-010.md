# ده تسک نخست — شرکت مدار

این نسخه از دادهٔ مرجع tasks-001-010.json تهیه شده است. اکنون تمرین‌ها از `/ccna/learning` به Workspace و ارزیاب وضعیت متصل‌اند؛ JSON مرجع Runtime است.

001 و 004 بررسی فهم درس جدا دارند؛ ۸ تسک دیگر از وضعیت دستگاه و predicateهای `lib/content/cisco-learning.ts` ارزیابی می‌شوند.

## توپولوژی و قرارداد مشترک

- 001 تا 008: PC-A Gi0/0 ↔ SW1 Gi0/1 و PC-B Gi0/0 ↔ SW1 Gi0/2.
- 009 و 010: PC-A در جای قبلی؛ SW1 Gi0/3 ↔ SW2 Gi0/1؛ PC-B Gi0/0 ↔ SW2 Gi0/2.
- SW1/SW2 نقش switch و PCها نقش host دارند؛ قالب‌های مسیر جدید با شناسهٔ مستقل از 109 لب قبلی منتشر شده‌اند.
- فرمان IP روی PC، قرارداد همین کنسول آموزشی است؛ Windows/Linux CLI نیست.
- رمزهای نمونه فقط آزمایشگاهی‌اند؛ این مدل رمزنگاری واقعی اجرا نمی‌کند.
- هر وضعیت شروع از نسخهٔ سالم تسک قبلی و سپس تنظیم خراب صریح ساخته می‌شود. دادهٔ Resume کاربر هدف Fault نیست.

## Task 001 — اولین اتصال به Switch

مرحله: S01 · نوع: inspection · زمان پیشنهادی: 5 دقیقه

سناریو: اولین روز کاری تو در شرکت مدار است. قبل از تغییر تنظیمات، دستگاه و پورت‌های دو کارمند را شناسایی کن.

پیش‌نیاز: ندارد

پیش‌درس: Console برای ورود به CLI است. علامت > حالت User EXEC و # حالت Privileged EXEC را نشان می‌دهد؛ خود علامت را تایپ نکن.

توپولوژی: base؛ دستگاه هدف: sw1.

وضعیت شروع: دو کابل متصل‌اند؛ SW1 با Hostname برابر Switch، پورت‌های Access در VLAN 1 و PCها بدون IP شروع می‌کنند. هنوز گزارش بررسی نداده‌ای.

هدف دقیق: کنسول SW1 را انتخاب کن، حالت Privileged را باز کن و پورت‌های PC-A و PC-B و نوع مدل دستگاه را گزارش بده.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- sw1: کنسول SW1 را باز کن و با ? فرمان‌های همین Mode را ببین. دلیل: فرمان معتبر به نقش دستگاه و Mode بستگی دارد.
- sw1: با enable وارد Privileged شو؛ show version و show interfaces status را بررسی کن. دلیل: قبل از تغییر باید نوع دستگاه و پورت‌های واقعی را بشناسی.

### Hint اختیاری

1. از PC شروع نکن؛ دستگاه هدف SW1 است.
2. تغییر > به # را با enable مشاهده کن.
3. show interfaces status را با دو کابل نقشه مقایسه کن.

### بررسی موفقیت

sw1: مدل آموزشی Switch و اتصال Gi0/1 و Gi0/2 را مشاهده کن؛ خروجی را با نقشه تطبیق بده.

روی sw1:

```text
show version
show interfaces status
show running-config
```

### Variation عیب‌یابی

001-f1: کابل PC-B قطع شده است.

شکست مورد انتظار: Gi0/2 دیگر اتصال عملی ندارد.

تعمیر: کابل را بین PC-B Gi0/0 و SW1 Gi0/2 برگردان و وضعیت را دوباره بخوان.

### راه‌حل کامل

روی sw1:

```text
enable
show version
show interfaces status
show running-config
```

چرا کار می‌کند: enable سطح فرمان‌ها را تغییر می‌دهد، نه پیکربندی شبکه را. پورت متصل ممکن است هنوز IP نداشته باشد. show version این سایت صریحاً مدل آموزشی است؛ Firmware، Uptime یا IOS واقعی را ثابت نمی‌کند.

### معیار قبولی

- 001-report: گزارش سه پاسخ صحیح و تطبیق پورت با نقشه و خروجی؛ صرف تایپ Show کافی نیست.

نوع ارزیابی: guided-evidence-not-automatic.

مهارت‌ها: Console، Help، EXEC modes، Interface inspection.

نگاشت موتور: Existing console/help/show commands.

محدودیت: ارزیاب پاسخ در UI فعلی وجود ندارد؛ تیک خودکار برای این مشاهده جعل نشود.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-addressing.

پرسش‌های مرور و پاسخ مرجع:

- PC-A و PC-B روی چه پورت‌هایی هستند؟ پاسخ: PC-A روی Gi0/1 و PC-B روی Gi0/2ِ SW1.
- تفاوت > و # چیست؟ پاسخ: User EXEC و Privileged EXEC؛ تنظیمات Global با configure terminal باز می‌شود.
- آیا show version ثابت می‌کند Cisco IOS واقعی اجرا می‌شود؟ پاسخ: خیر؛ خروجی مدل آموزشی است.

منابع: [ccna-current](https://www.cisco.com/c/en/us/training-events/training-certifications/exams/current-list/ccna-200-301.html).

## Task 002 — نام‌گذاری، محدودکردن دسترسی و Save

مرحله: S01 · نوع: build · زمان پیشنهادی: 8 دقیقه

سناریو: مسئول IT نام مشخص برای Switch می‌خواهد. تا آماده‌شدن مدیریت امن، هیچ ورود راه‌دوری لازم نیست.

پیش‌نیاز: Task 001

پیش‌درس: Hostname نام دستگاه است. VTY محل ورود راه‌دور است، نه Console. Running تنظیمات فعلی و Startup نسخهٔ ذخیره‌شده است.

توپولوژی: base؛ دستگاه هدف: sw1.

وضعیت شروع: Hostname هنوز Switch است؛ VTYها محدود نشده و تنظیمات نهایی ذخیره نشده‌اند.

هدف دقیق: Hostname را SW1 کن؛ حساب آزمایشگاهی netadmin بساز؛ ورود تمام VTYهای 0 تا 15 را ببند و تنظیمات نهایی را ذخیره کن.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- sw1: نام و حساب محلی را در Global تنظیم کن؛ VTYها را انتخاب و transport input none اعمال کن؛ سپس از Configuration خارج شو و Save کن. دلیل: دسترسی غیرضروری بسته می‌ماند و نسخهٔ نهایی ذخیره می‌شود.

### Hint اختیاری

1. ابتدا enable و configure terminal.
2. line vty 0 15 تمام خطوط مدل را انتخاب می‌کند.
3. transport input none؛ سپس end و copy running-config startup-config.

### بررسی موفقیت

sw1: Hostname، حساب و محدودیت VTY در Running و Startup نهایی یکسان‌اند.

روی sw1:

```text
show running-config
show startup-config
```

### Variation عیب‌یابی

002-f1: بعد از Save، ورود VTYهای 5 تا 15 دوباره باز شده است.

شکست مورد انتظار: هم سیاست دسترسی ناقص است و هم Startup با Running نهایی یکی نیست.

راه‌حل Variation:

روی sw1:

```text
enable
configure terminal
line vty 0 15
login local
transport input none
end
copy running-config startup-config
```

### راه‌حل کامل

روی sw1:

```text
enable
configure terminal
hostname SW1
username netadmin privilege 15 secret LabOnly-001
line vty 0 15
login local
transport input none
end
copy running-config startup-config
```

چرا کار می‌کند: VTY بسته یعنی فعلاً ورود شبکه‌ای لازم نیست؛ Console همچنان مسیر کار است. حساب برای درس‌های بعدی آماده می‌شود، ولی بستن VTY به معنی حفاظت Console یا enable نیست. Secret در موتور مخزن امن یا رمزنگاری واقعی ندارد. این هدف Hardening کامل نیست.

### معیار قبولی

- 002-hostname / sw1: hostname برابر SW1 است. دلیل شکست: نام SW1 را روی Switch هدف تنظیم کن.
- 002-user / sw1: netadmin با kind=secret و privilege=15 وجود دارد؛ رمز فقط آزمایشگاهی است. دلیل شکست: حساب آزمایشگاهی netadmin را روی SW1 بساز.
- 002-vty / sw1: تمام 16 VTY دارای loginLocal=true و transport خالی‌اند. دلیل شکست: محدودیت را برای تمام VTYهای 0 تا 15 اعمال کن.
- 002-save / sw1: startupSaved و startupMatchesRunning هر دو true هستند. دلیل شکست: بعد از آخرین تغییر دوباره Save کن.

نوع ارزیابی: live-state.

مهارت‌ها: Hostname، Local-user concepts، VTY restriction، Configuration persistence.

نگاشت موتور: Hostname, management.users/vty and startup state.

محدودیت: enable secret و حفاظت Console پشتیبانی نمی‌شوند؛ امنیت کامل ادعا نشود.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-security.

منابع: [line-access](https://netascode.cisco.com/docs/data_models/iosxe/device/line/).

## Task 003 — اولین ارتباط دو PC

مرحله: S02 · نوع: build · زمان پیشنهادی: 8 دقیقه

سناریو: دو کارمند می‌خواهند در شبکهٔ داخلی به هم دسترسی داشته باشند؛ هنوز Router نداریم.

پیش‌نیاز: Task 002

پیش‌درس: IPv4 و Mask تعیین می‌کنند مقصد در همان Subnet است یا نه. برای ارتباط دو میزبان در همان Subnet و VLAN، Gateway لازم نیست.

توپولوژی: base؛ دستگاه هدف: pc-a، pc-b، sw1.

وضعیت شروع: دو Host بدون IP؛ پورت‌ها در VLAN 1 و کابل‌ها متصل‌اند.

هدف دقیق: PC-A را 192.168.10.10/24 و PC-B را 192.168.10.20/24 کن؛ ارتباط دوطرفه برقرار شود.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- pc-a: IPv4 و Mask را روی PC-A تنظیم کن. دلیل: آدرس باید متعلق به خود این میزبان و یکتا باشد.
- pc-b: PC-B را در همان Subnet تنظیم کن و از هر دو طرف ping بگیر. دلیل: Self-ping یا موفقیت تنها یک جهت، هدف دوطرفه را ثابت نمی‌کند.

### Hint اختیاری

1. Mask یک /24 برابر 255.255.255.0 است.
2. روی Host از ip address و سپس ipconfig استفاده کن.
3. PC-A: ip address 192.168.10.10 255.255.255.0؛ PC-B: همان Mask و آدرس .20.

### بررسی موفقیت

pc-a: PC-B با آدرس خودش پاسخ می‌دهد.

روی pc-a:

```text
ipconfig
ping 192.168.10.20
```

pc-b: PC-A پاسخ می‌دهد.

روی pc-b:

```text
ipconfig
ping 192.168.10.10
```

### Variation عیب‌یابی

003-f1: PC-B اشتباهاً در شبکهٔ دیگری قرار گرفته است.

شکست مورد انتظار: آدرس هدف به PC-B تعلق ندارد و Same-subnet connectivity برقرار نیست.

راه‌حل Variation:

روی pc-b:

```text
ip address 192.168.10.20 255.255.255.0
```

### راه‌حل کامل

روی pc-a:

```text
ip address 192.168.10.10 255.255.255.0
```

روی pc-b:

```text
ip address 192.168.10.20 255.255.255.0
```

چرا کار می‌کند: هر دو آدرس در 192.168.10.0/24 هستند و از Access portهای VLAN 1 عبور می‌کنند. Router برای این مقصد محلی لازم نیست. نبود Gateway در این تمرین خطا نیست.

### معیار قبولی

- 003-addresses / pc-a: PC-A روی Gi0/0 برابر .10/24 و PC-B برابر .20/24 است؛ هر IP تنها یک مالک دارد. دلیل شکست: IP، Mask و یکتایی آدرس‌های هر دو PC را بررسی کن.
- 003-path / sw1: دو کابل base موجود، پورت‌ها فعال و در Access VLAN 1 هستند. دلیل شکست: کابل و VLAN پورت‌های Gi0/1 و Gi0/2 را بررسی کن.
- 003-reach / pc-a: reachesDevice در هر دو جهت بین pc-a و pc-b موفق است. دلیل شکست: هر PC باید دستگاه دیگر را با IP خودش پیدا کند.

نوع ارزیابی: live-state.

مهارت‌ها: IPv4، Mask، Same-subnet connectivity، ping.

نگاشت موتور: Host addressing and shared live connectivity.

محدودیت: فرمان IP این کنسول دستور Windows/Linux نیست.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-addressing.

منابع: [ccna-current](https://www.cisco.com/c/en/us/training-events/training-certifications/exams/current-list/ccna-200-301.html)، [ccna-v2](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301_CCNA_v2.0_Exam_Topics_PDF.pdf).

## Task 004 — تفاوت ARP و MAC address table

مرحله: S02 · نوع: inspection · زمان پیشنهادی: 7 دقیقه

سناریو: همکارت می‌پرسد PC چگونه MAC مقصد را پیدا می‌کند و Switch چگونه پورت خروجی را انتخاب می‌کند.

پیش‌نیاز: Task 003

پیش‌درس: ARP در IPv4 آدرس IP محلی را به MAC مرتبط می‌کند. MAC table در Switch، MAC و VLAN را به پورت مرتبط می‌کند.

توپولوژی: base؛ دستگاه هدف: pc-a، sw1.

وضعیت شروع: ارتباط برقرار است؛ جدول‌های زیر فقط نمونهٔ آموزشی‌اند و خروجی موتور نیستند.

هدف دقیق: از IP مقصد تا MAC و پورت خروجی را توضیح بده و مغایرت جدول با کابل را تشخیص بده.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- pc-a: در جدول آموزشی ARP، MAC مربوط به 192.168.10.20 را پیدا کن. دلیل: میزبان برای فرستادن Frame محلی به MAC مقصد نیاز دارد.
- sw1: همان MAC را در MAC table نمونه دنبال کن و پورت را با نقشه تطبیق بده. دلیل: Switch از جدول Forwarding استفاده می‌کند، نه جدول ARP میزبان.

### Hint اختیاری

1. جدول میزبان و Switch دو کار متفاوت دارند.
2. اول IP را به MAC و بعد MAC را به Port نگاشت کن.
3. 192.168.10.20 → 02:00:00:00:00:20 → VLAN 1 / Gi0/2.

### شاهد آموزشی — خروجی واقعی موتور نیست

ARP روی PC-A: `192.168.10.20 → 02:00:00:00:00:20`

MAC table روی SW1: `VLAN 1 / 02:00:00:00:00:20 → Gi0/2`


فرمان‌های مرجع زیر در این شبیه‌ساز اجرا نمی‌شوند:

روی pc-a:

```text
arp -a
```

روی sw1:

```text
show mac address-table dynamic
```


### بررسی موفقیت

sw1: پاسخ زنجیرهٔ IP→MAC→Port و تفاوت دو جدول را بررسی کن؛ موتور این جدول‌ها را چاپ نمی‌کند.

### Variation عیب‌یابی

004-f1: در نمونهٔ آموزشی MAC مربوط به PC-B اشتباهاً Gi0/1 درج شده؛ کابل تغییر نکرده است.

شکست مورد انتظار: جدول نمونه با اتصال PC-B به Gi0/2 ناسازگار است.

تعمیر: مغایرت را گزارش و جدول آموزشی را به Gi0/2 اصلاح کن؛ فرمان Clear خیالی وارد نکن.

### راه‌حل کامل

PC-A برای مقصد محلی .20 به MAC برابر 02:00:00:00:00:20 نیاز دارد. SW1 این MAC را در VLAN 1 به Gi0/2 مرتبط می‌کند. ورودی Gi0/1 با نقشه سازگار نیست.

چرا کار می‌کند: ARP نگاشت IP↔MAC است و MAC table نگاشت VLAN/MAC↔Port. جدول ARP خود Switch همهٔ میزبان‌های عبوری را الزاماً شامل نمی‌شود. این تمرین مدل MAC learning، ARP cache یا حملهٔ ARP ایجاد نمی‌کند.

### معیار قبولی

- 004-report: زنجیرهٔ صحیح IP→MAC→Port، تفاوت جدول‌ها و Fault نمونه توضیح داده شود؛ نیازمند بررسی پاسخ خارج از grader فعلی است.

نوع ارزیابی: guided-evidence-not-automatic.

مهارت‌ها: Ethernet، ARP، MAC learning concepts، Layer 2 versus Layer 3.

نگاشت موتور: Existing nodes as conceptual context only.

محدودیت: ARP/MAC commands پشتیبانی نمی‌شوند؛ نمونه‌ها واقعی یا خودکار معرفی نشوند.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-addressing.

پرسش‌های مرور و پاسخ مرجع:

- اگر MAC در جدول نیست، آیا به معنی نبودن IP است؟ پاسخ: نه؛ جدول یادگیری MAC و آدرس‌دهی IP دو وضعیت متفاوت‌اند.
- جدول آموزشی با MAC مربوط به PC-B روی Gi0/1 چه ایرادی دارد؟ پاسخ: با کابل واقعی PC-B روی Gi0/2 مطابقت ندارد.

منابع: [mac-arp](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst2960/software/release/12-2_53_se/configuration/guide/2960scg/swadmin.html).

## Task 005 — اولین VLANها

مرحله: S03 · نوع: change-request · زمان پیشنهادی: 10 دقیقه

سناریو: شرکت فروش و مالی را جدا می‌کند؛ دو واحد باید Broadcast domain جدا داشته باشند.

پیش‌نیاز: Task 003، Task 004

پیش‌درس: VLAN یک جداسازی Layer 2 است. ساخت VLAN به‌تنهایی پورت را عضو آن نمی‌کند؛ Access VLAN باید مشخص باشد.

توپولوژی: base؛ دستگاه هدف: sw1، pc-a، pc-b.

وضعیت شروع: وضعیت 003 حفظ شده: هر دو PC در VLAN 1 و 192.168.10.0/24؛ VLANهای 10 و 20 ساخته نشده‌اند.

هدف دقیق: VLAN 10 SALES برای PC-A و VLAN 20 FINANCE برای PC-B بساز؛ PC-B برابر 192.168.20.20/24 شود؛ جداسازی حفظ و Switch ذخیره شود.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- sw1: دو VLAN را بساز و Gi0/1 را Access VLAN 10 و Gi0/2 را Access VLAN 20 کن. دلیل: عضویت پورت، میزبان را در Broadcast domain مشخص قرار می‌دهد.
- pc-b: آدرس PC-B را مطابق شبکهٔ مالی تغییر بده. دلیل: طرح IP هر واحد باید با شبکهٔ مربوط به آن هماهنگ باشد.

### Hint اختیاری

1. پس از vlan وارد حالت مربوط به همان VLAN می‌شوی؛ با exit برگرد.
2. برای هر پورت switchport mode access و switchport access vlan را تنظیم کن.
3. Gi0/1→10، Gi0/2→20؛ سپس end و Save.

### بررسی موفقیت

sw1: نام و عضویت صحیح دو VLAN و Save نهایی.

روی sw1:

```text
show vlan brief
show interfaces switchport
show startup-config
```

pc-b: IP مالی صحیح و ping بین دو واحد فعلاً ناموفق است؛ هنوز Router نداریم.

روی pc-b:

```text
ipconfig
ping 192.168.10.10
```

### Variation عیب‌یابی

005-f1: VLAN 20 وجود دارد ولی Gi0/2 در VLAN 1 مانده است.

شکست مورد انتظار: عضویت پورت هدف غلط است، حتی اگر ping به علت IPها باز هم شکست بخورد.

راه‌حل Variation:

روی sw1:

```text
enable
configure terminal
interface gi0/2
switchport access vlan 20
end
copy running-config startup-config
```

### راه‌حل کامل

روی sw1:

```text
enable
configure terminal
vlan 10
name SALES
exit
vlan 20
name FINANCE
exit
interface gi0/1
switchport mode access
switchport access vlan 10
exit
interface gi0/2
switchport mode access
switchport access vlan 20
end
copy running-config startup-config
```

روی pc-b:

```text
ip address 192.168.20.20 255.255.255.0
```

چرا کار می‌کند: هر واحد VLAN و Subnet جدا دارد. بین VLANها به Routing نیاز داریم؛ بنابراین اینجا شکست ping انتظار می‌رود. اما شکست ping به‌تنهایی اثبات VLAN صحیح نیست؛ کابل، IP و عضویت پورت باید جدا بررسی شوند.

### معیار قبولی

- 005-vlans / sw1: VLAN 10 SALES و VLAN 20 FINANCE موجودند. دلیل شکست: VLAN و نام هر دو واحد را بساز.
- 005-access / sw1: Gi0/1 فعال در Access VLAN 10 و Gi0/2 فعال در Access VLAN 20 است؛ کابل‌های base صحیح‌اند. دلیل شکست: پورت واقعی هر PC را در VLAN درست قرار بده.
- 005-address / pc-b: PC-A برابر 192.168.10.10/24 و PC-B برابر 192.168.20.20/24 با آدرس‌های یکتا است. دلیل شکست: آدرس هر واحد را مطابق هدف تنظیم کن.
- 005-isolation-save / sw1: Route بین دو واحد وجود ندارد، ارتباط مستقیم دو PC برقرار نیست و Startup با Running نهایی یکسان است. دلیل شکست: جداسازی هدف و Save نهایی را بررسی کن.

نوع ارزیابی: live-state.

مهارت‌ها: VLAN، Access ports، Segmentation، Address planning.

نگاشت موتور: VLAN database and per-port access membership.

محدودیت: VLAN جایگزین Firewall یا کنترل دسترسی Layer 3 نیست.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-vlans.

منابع: [vlan-trunk](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html).

## Task 006 — رفع خرابی پورت مالی

مرحله: S03 · نوع: troubleshooting · زمان پیشنهادی: 8 دقیقه

سناریو: کابل مالی متصل است اما پورت پس از یک تغییر کار نمی‌کند؛ عضویت VLAN هم اشتباه شده است.

پیش‌نیاز: Task 005

پیش‌درس: کابل متصل، پورت shutdown را فعال نمی‌کند. وضعیت مدیریتی و عضویت VLAN دو ایراد مستقل‌اند.

توپولوژی: base؛ دستگاه هدف: sw1، pc-b.

وضعیت شروع: Gi0/2 در VLAN 10 و shutdown است؛ PC-B همچنان آدرس صحیح مالی .20/24 را دارد.

هدف دقیق: Gi0/2 را فعال و عضو VLAN 20 کن؛ آدرس مالی و جداسازی را حفظ و تنظیمات نهایی را ذخیره کن.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- sw1: قبل از تغییر، Status و Switchport را بخوان؛ فقط دو تنظیم خراب Gi0/2 را اصلاح کن. دلیل: Reset کل شبکه، تنظیمات سالم و پیشرفت کار را از بین می‌برد.

### Hint اختیاری

1. ابتدا کابل، سپس Admin state، سپس Access VLAN.
2. show interfaces status و show interfaces switchport.
3. Gi0/2: switchport access vlan 20 و no shutdown؛ سپس Save.

### بررسی موفقیت

sw1: Gi0/2 فعال و عضو VLAN مالی است.

روی sw1:

```text
show interfaces status
show interfaces switchport
show vlan brief
```

pc-b: آدرس مالی تغییر نکرده است.

روی pc-b:

```text
ipconfig
```

### Variation عیب‌یابی

006-f1: پس از تعمیر پورت، کابل PC-B قطع می‌شود.

شکست مورد انتظار: پورت Admin-up است ولی اتصال عملی کابل ندارد.

تعمیر: کابل را به Gi0/2 برگردان؛ no shutdown را بی‌هدف تکرار نکن.

### راه‌حل کامل

روی sw1:

```text
enable
configure terminal
interface gi0/2
switchport mode access
switchport access vlan 20
no shutdown
end
copy running-config startup-config
```

چرا کار می‌کند: فقط فعال‌کردن پورت کافی نیست؛ VLAN غلط هم باید اصلاح شود. برعکس، VLAN صحیح روی پورت خاموش ارتباط نمی‌سازد. جداسازی فروش و مالی باید بعد از تعمیر حفظ شود.

### معیار قبولی

- 006-port / sw1: Gi0/2 فعال، Access و VLAN 20 است و به pc-b:Gi0/0 وصل است. دلیل شکست: کابل، Admin state و VLAN پورت مالی را جدا بررسی کن.
- 006-preserve / pc-b: آدرس 192.168.20.20/24 و تنظیمات سالم فروش حفظ شده و جداسازی برقرار است. دلیل شکست: تنظیمات سالم را تغییر نده؛ هدف فقط تعمیر مالی است.
- 006-save / sw1: Startup با Running نهایی مطابق است. دلیل شکست: تعمیر نهایی را Save کن.

نوع ارزیابی: live-state.

مهارت‌ها: Admin versus link state، VLAN faults، Minimal repair.

نگاشت موتور: shutdown/no shutdown, VLAN and cable-aware status.

محدودیت: نبود ارتباط بین VLANها در این مرحله طبیعی است.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-vlans.

منابع: [vlan-trunk](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html).

## Task 007 — انتقال کارمند و Subnetting

مرحله: S02 / S03 · نوع: change-request · زمان پیشنهادی: 10 دقیقه

سناریو: کارمند مالی به تیم فروش منتقل می‌شود؛ شبکهٔ فروش نیز باید از /24 به /26 تغییر کند.

پیش‌نیاز: Task 006

پیش‌درس: /26 برابر 255.255.255.192 است. در 192.168.10.0/26، Network برابر .0، Broadcast برابر .63 و میزبان‌های قابل استفاده .1 تا .62 هستند.

توپولوژی: base؛ دستگاه هدف: sw1، pc-a، pc-b.

وضعیت شروع: PC-A در VLAN 10 با .10/24 و PC-B در VLAN 20 با 192.168.20.20/24 است.

هدف دقیق: هر دو PC در Access VLAN 10 باشند؛ PC-A برابر 192.168.10.10/26 و PC-B برابر 192.168.10.20/26 با اتصال دوطرفه.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- sw1: فقط پورت PC-B را به VLAN فروش منتقل کن و ذخیره کن. دلیل: انتقال واحد کاری، عضویت Layer 2 را هم تغییر می‌دهد.
- pc-a: Mask هر دو PC و آدرس PC-B را مطابق طرح /26 تغییر بده. دلیل: VLAN صحیح بدون طرح IP صحیح کافی نیست.

### Hint اختیاری

1. داشتن سه بخش اول یکسان در IP کافی نیست؛ Mask مرز Subnet را مشخص می‌کند.
2. Gi0/2 باید VLAN 10 شود؛ Mask هر دو 255.255.255.192.
3. PC-A .10/26 و PC-B .20/26؛ .70/26 در شبکهٔ بعدی است.

### بررسی موفقیت

sw1: هر دو Access port در VLAN 10 هستند.

روی sw1:

```text
show vlan brief
```

pc-a: .10/26 و ارتباط با PC-B.

روی pc-a:

```text
ipconfig
ping 192.168.10.20
```

pc-b: .20/26 و ارتباط با PC-A.

روی pc-b:

```text
ipconfig
ping 192.168.10.10
```

### Variation عیب‌یابی

007-f1: PC-B اشتباهاً .70/26 شده است.

شکست مورد انتظار: PC-B در 192.168.10.64/26 است، نه Subnet هدف .0/26.

راه‌حل Variation:

روی pc-b:

```text
ip address 192.168.10.20 255.255.255.192
```

### راه‌حل کامل

روی sw1:

```text
enable
configure terminal
interface gi0/2
switchport access vlan 10
end
copy running-config startup-config
```

روی pc-a:

```text
ip address 192.168.10.10 255.255.255.192
```

روی pc-b:

```text
ip address 192.168.10.20 255.255.255.192
```

چرا کار می‌کند: دو PC هم VLAN و هم Subnet مشترک دارند. حتی اگر ping با Mask اشتباه در نمونه‌ای موفق شود، طرح /26 هنوز اجرا نشده؛ معیار قبولی باید Mask دقیق را بررسی کند.

### معیار قبولی

- 007-address / pc-a: آدرس‌های یکتای .10 و .20 با Mask دقیق 255.255.255.192 روی دو Host هستند. دلیل شکست: Subnet، IP و Mask هر دو PC را اصلاح کن.
- 007-membership / sw1: هر دو Access port فعال، کابل‌های base صحیح و Access VLAN هر دو 10 است. دلیل شکست: پورت PC-B هنوز باید به فروش منتقل شود.
- 007-connect-save / sw1: Reachability دوطرفهٔ named-device و Startup مطابق Running است. دلیل شکست: ارتباط واقعی دو PC و Save تغییر Switch را بررسی کن.

نوع ارزیابی: live-state.

مهارت‌ها: Subnet boundaries، Change requests، VLAN/IP consistency.

نگاشت موتور: Host mask and access membership.

محدودیت: ping جایگزین بررسی Mask دقیق نیست.

## Task 008 — اولین اتصال IPv6

مرحله: S02 · نوع: build · زمان پیشنهادی: 8 دقیقه

سناریو: شرکت بدون حذف IPv4 می‌خواهد شبکهٔ فروش Dual-stack شود.

پیش‌نیاز: Task 007

پیش‌درس: IPv6 به‌جای Mask نقطه‌ای، Prefix length دارد. :: صفرهای متوالی را کوتاه می‌کند؛ /64 بخش شبکه را مشخص می‌کند. آدرس‌های 2001:db8 برای مستندسازی تمرین‌اند.

توپولوژی: base؛ دستگاه هدف: pc-a، pc-b، sw1.

وضعیت شروع: IPv4 و VLAN 10 برقرار است؛ دو Host IPv6 ندارند.

هدف دقیق: PC-A برابر 2001:db8:10::10/64 و PC-B برابر 2001:db8:10::20/64 شود؛ ارتباط دوطرفهٔ IPv4 و IPv6 حفظ شود.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- pc-a: IPv6 /64 را روی PC-A اضافه کن؛ IPv4 را حذف نکن. دلیل: Dual-stack دو پیکربندی مستقل است.
- pc-b: PC-B را در همان Prefix تنظیم و هر دو خانواده را تست کن. دلیل: موفقیت یک خانوادهٔ IP، خانوادهٔ دیگر را ثابت نمی‌کند.

### Hint اختیاری

1. برای دو میزبان روی همین VLAN و Prefix، Gateway لازم نیست.
2. روی Host فرمان ipv6 address را با /64 وارد کن.
3. PC-A: 2001:db8:10::10/64؛ PC-B: 2001:db8:10::20/64.

### بررسی موفقیت

pc-a: هر دو خانواده به PC-B می‌رسند.

روی pc-a:

```text
ipconfig
ping 2001:db8:10::20
ping 192.168.10.20
```

pc-b: هر دو خانواده به PC-A می‌رسند.

روی pc-b:

```text
ipconfig
ping 2001:db8:10::10
ping 192.168.10.10
```

### Variation عیب‌یابی

008-f1: PC-B در Prefix اشتباه IPv6 قرار گرفته است.

شکست مورد انتظار: هدف IPv6 صحیح نیست؛ IPv4 باید همچنان برقرار بماند.

راه‌حل Variation:

روی pc-b:

```text
ipv6 address 2001:db8:10::20/64
```

### راه‌حل کامل

روی pc-a:

```text
ipv6 address 2001:db8:10::10/64
```

روی pc-b:

```text
ipv6 address 2001:db8:10::20/64
```

چرا کار می‌کند: IPv6 و IPv4 هر کدام باید آدرس، Prefix/Mask و مسیر صحیح داشته باشند. اضافه‌کردن IPv6 نباید با تغییر IPv4 سالم انجام شود. این تمرین خروجی ND یا Packet capture تولید نمی‌کند.

### معیار قبولی

- 008-v6 / pc-a: دو آدرس IPv6 هدف یکتا و با Prefix دقیق /64 وجود دارند. دلیل شکست: آدرس و Prefix هر دو Host را بررسی کن.
- 008-preserve / sw1: IPv4 تسک 007، VLAN 10 و کابل‌های base حفظ شده‌اند. دلیل شکست: برای ساخت IPv6، IPv4 یا VLAN سالم را تغییر نده.
- 008-dual / pc-b: reachesDevice بین pc-a و pc-b در هر دو جهت و هر دو خانواده موفق است. دلیل شکست: هر چهار مسیر واقعی را بررسی کن؛ Self-ping کافی نیست.

نوع ارزیابی: live-state.

مهارت‌ها: IPv6، Prefix، Dual-stack، Non-disruptive change.

نگاشت موتور: IPv6 host addressing and shared ping.

محدودیت: ND جزئی و Packet capture تأیید نشده‌اند و شرط قبولی نیستند.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-addressing.

منابع: [ccna-current](https://www.cisco.com/c/en/us/training-events/training-certifications/exams/current-list/ccna-200-301.html)، [ccna-v2](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301_CCNA_v2.0_Exam_Topics_PDF.pdf).

## Task 009 — اضافه‌شدن Switch دوم

مرحله: S03 · نوع: build · زمان پیشنهادی: 15 دقیقه

سناریو: PC-B به اتاق دیگری منتقل می‌شود؛ از SW2 باید همچنان به فروش و PC-A دسترسی داشته باشد.

پیش‌نیاز: Task 008

پیش‌درس: Access port یک VLAN را برای میزبان فراهم می‌کند. 802.1Q trunk VLANهای مجاز را بین Switchها حمل می‌کند؛ Allowed list در هر دو سر باید مطابق نیاز باشد.

توپولوژی: expanded؛ دستگاه هدف: sw1، sw2، pc-a، pc-b.

وضعیت شروع: PCها آدرس‌های قبلی دارند؛ PC-B به SW2 Gi0/2 منتقل شده؛ SW2 تازه است و دو سر لینک بین Switchها هنوز Access VLAN 1 هستند.

هدف دقیق: SW2 را نام‌گذاری و دسترسی اولیه‌اش را محدود کن؛ VLAN 10 را روی آن بساز؛ Trunk فقط VLAN 10 را حمل کند و ارتباط Dual-stack دوطرفه بازگردد.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- sw1: Gi0/3 را Trunk کن و فقط VLAN 10 را مجاز کن. دلیل: این لینک دیگر پورت میزبان نیست؛ اتصال بین Switchهاست.
- sw2: VLAN فروش، Access port میزبان و Trunk را تنظیم کن؛ نام و VTY مطابق سیاست اولیه و Save نهایی را انجام بده. دلیل: Switch تازه هم طرح VLAN و هم سیاست مدیریت قبلی را نیاز دارد.

### Hint اختیاری

1. نقشهٔ جدید را قبل از فرمان بررسی کن؛ PC-B دیگر روی SW1 نیست.
2. SW1 Gi0/3 و SW2 Gi0/1 Trunk؛ SW2 Gi0/2 Access VLAN 10.
3. switchport trunk allowed vlan 10 را در هر دو سر و Save را روی هر دو Switch انجام بده.

### بررسی موفقیت

sw1: Gi0/3 Trunk با Allowed list دقیق 10 است.

روی sw1:

```text
show interfaces trunk
show vlan brief
show startup-config
```

sw2: VLAN 10، پورت‌های هدف، Hostname و VTY و Save صحیح‌اند.

روی sw2:

```text
show interfaces trunk
show vlan brief
show running-config
show startup-config
```

pc-a: PC-B از مسیر SW1→SW2 پاسخ می‌دهد.

روی pc-a:

```text
ping 192.168.10.20
ping 2001:db8:10::20
```

pc-b: جهت برگشت برقرار است.

روی pc-b:

```text
ping 192.168.10.10
ping 2001:db8:10::10
```

### Variation عیب‌یابی

009-f1: Trunk روی SW2 فقط VLAN 20 را مجاز کرده است.

شکست مورد انتظار: VLAN فروش از لینک بین Switchها عبور نمی‌کند.

راه‌حل Variation:

روی sw2:

```text
enable
configure terminal
interface gi0/1
switchport trunk allowed vlan 10
end
copy running-config startup-config
```

### راه‌حل کامل

روی sw1:

```text
enable
configure terminal
interface gi0/3
switchport mode trunk
switchport trunk allowed vlan 10
no shutdown
end
copy running-config startup-config
```

روی sw2:

```text
enable
configure terminal
hostname SW2
username netadmin privilege 15 secret LabOnly-001
vlan 10
name SALES
exit
interface gi0/1
switchport mode trunk
switchport trunk allowed vlan 10
no shutdown
exit
interface gi0/2
switchport mode access
switchport access vlan 10
no shutdown
exit
line vty 0 15
login local
transport input none
end
copy running-config startup-config
```

چرا کار می‌کند: VLAN 10 روی هر دو Switch وجود دارد؛ Access portها میزبان‌ها را عضو آن می‌کنند و Trunk مسیر بین دو Switch است. محدودکردن Allowed list به 10 نیاز همین Change را پوشش می‌دهد؛ VLANهای دیگر بدون نیاز باز نمی‌شوند. این هنوز STP یا EtherChannel نیست.

### معیار قبولی

- 009-topology / sw1: هر سه کابل expanded به پورت‌های دقیق متصل و فعال‌اند. دلیل شکست: مسیر کابل PC-B و لینک Gi0/3↔Gi0/1 را بررسی کن.
- 009-vlan / sw2: VLAN 10 SALES در هر دو Switch و Access فعال VLAN 10 روی SW1 Gi0/1 و SW2 Gi0/2 وجود دارد. دلیل شکست: VLAN و پورت میزبان باید در هر دو Switch صحیح باشند.
- 009-trunk / sw1: SW1 Gi0/3 و SW2 Gi0/1 فعال و Trunk با Allowed list دقیق [10] و Native VLAN برابر 1 هستند. دلیل شکست: هر دو سر Trunk باید VLAN فروش را طبق طرح حمل کنند.
- 009-security / sw2: Hostname SW2، حساب netadmin، loginLocal و transport خالی روی تمام VTYها برقرار است؛ سیاست SW1 از 002 حفظ شده است. دلیل شکست: سیاست دسترسی Switch تازه و قبلی را حفظ کن.
- 009-dual-save / pc-a: آدرس‌های دقیق 007/008 با مالک یکتا، چهار مسیر named-device و Save مطابق روی هر دو Switch برقرارند. دلیل شکست: Dual-stack، یکتایی آدرس و Save هر دو Switch را بررسی کن.

نوع ارزیابی: live-state.

مهارت‌ها: 802.1Q trunk، Allowed VLAN، Topology expansion، Policy reuse.

نگاشت موتور: Two instances of existing switch model; no new device type.

محدودیت: این قالب چهار دستگاه دارد؛ لب ccna-topology-017 با شش دستگاه معادل آن نیست و پورت‌ها باید جدا نگاشت شوند.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-topology-017.

منابع: [vlan-trunk](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html)، [line-access](https://netascode.cisco.com/docs/data_models/iosxe/device/line/).

## Task 010 — تحویل شبکه و بررسی تغییر غیرمجاز

مرحله: S01 / S02 / S03 · نوع: timed-capstone / security-incident · زمان پیشنهادی: 20 دقیقه

سناریو: قبل از تحویل، اتصال فروش قطع شده و یک تغییر غیرمجاز در مدیریت SW2 دیده می‌شود. شبکه را با کمترین تغییر بازیابی کن و علت‌ها را گزارش بده.

پیش‌نیاز: Task 009

پیش‌درس: از Host و کابل به Access port و Trunk برس؛ تنظیمات مدیریتی را جدا بررسی کن. موفقیت ping، امنیت یا Save را ثابت نمی‌کند. زمان، معیار عملکرد است نه مجوز موفقیت ساختگی.

توپولوژی: expanded؛ دستگاه هدف: sw1، sw2، pc-a، pc-b.

وضعیت شروع: SW1 Gi0/1 خاموش، Allowed list در SW2 Gi0/1 برابر 20 و VTYهای SW2 دارای transport input all هستند. آدرس‌ها و کابل‌ها سالم‌اند.

هدف دقیق: تمام وضعیت هدف 009 را بازیابی کن: ارتباط Dual-stack دوطرفه، VTY بسته و Save هر دو Switch. سه علت و سه تعمیر را توضیح بده.

### مسیر انجام

راه‌حل را ابتدا پنهان نگه دارید؛ کاربر ابتدا هدف و راهنمای کم‌جزئیات را می‌بیند.

- pc-a: آدرس و اتصال را بررسی کن؛ نتیجهٔ ping را دلیل کامل ندان. دلیل: باید خرابی Host را از خرابی مسیر جدا کنی.
- sw1: Status و VLAN پورت PC-A و دو سر Trunk را بررسی و تغییرهای خراب را اصلاح کن. دلیل: دو Fault مسیر مستقل وجود دارند.
- sw2: سیاست VTY را با طرح مقایسه کن؛ ورود غیرضروری را ببند؛ تنظیمات نهایی را ذخیره و دوباره بررسی کن. دلیل: ارتباط کاربر و امنیت مدیریت دو معیار جدا هستند.

### Hint اختیاری

1. از کابل و پورت Access شروع کن؛ همهٔ تنظیمات را Reset نکن.
2. SW1 Gi0/1، SW2 Gi0/1 و VTYهای SW2 سه محل خرابی‌اند.
3. no shutdown، allowed vlan 10 و transport input none؛ سپس Save هر دو.

### بررسی موفقیت

sw1: وضعیت هدف 009 روی SW1 بازیابی شده است.

روی sw1:

```text
show interfaces status
show interfaces trunk
show vlan brief
show running-config
show startup-config
```

sw2: Trunk، VTY و Save نهایی صحیح‌اند.

روی sw2:

```text
show interfaces status
show interfaces trunk
show running-config
show startup-config
```

pc-a: دو مسیر از PC-A برقرارند.

روی pc-a:

```text

ping 2001:db8:10::20
```

pc-b: دو مسیر برگشت برقرارند.

روی pc-b:


### Variation عیب‌یابی

010-f1: در اجرای Variation از وضعیت سالم 009 شروع کن؛ به‌جای خاموشی Access port، VLAN آن را اشتباه کن. Faultهای Trunk و VTY همان Faultهای اصلی‌اند.

شکست مورد انتظار: PC-B در VLAN اشتباه است؛ تکرار no shutdown این Fault را حل نمی‌کند.

راه‌حل Variation:

روی sw2:

```text
enable
configure terminal
interface gi0/2
switchport access vlan 10
exit
interface gi0/1
switchport trunk allowed vlan 10
exit
line vty 0 15
login local
transport input none
end
copy running-config startup-config
```

### راه‌حل کامل

روی sw1:

```text
enable
configure terminal
interface gi0/1
no shutdown
end
copy running-config startup-config
```

روی sw2:

```text
enable
configure terminal
interface gi0/1
switchport trunk allowed vlan 10
exit
line vty 0 15
login local
transport input none
end
copy running-config startup-config
```

خاموشی Gi0/1 مسیر PC-A را قطع کرده؛ Allowed VLAN اشتباه، فروش را از Trunk حذف کرده؛ transport all سیاست مدیریت را نقض کرده است. هر سه را اصلاح، هر دو Switch را Save و هر چهار ping را بررسی کن. در Variation، Access VLAN 20ِ PC-B باید به 10 برگردد.

چرا کار می‌کند: راه‌حل درست کم‌دامنه است و تنظیمات سالم را حفظ می‌کند. VTY باز در این مدل به معنی وجود سرویس رمزنگاری واقعی نیست، اما با سیاست محتوای درس ناسازگار است. یک ping موفق، سه ایراد یا Save را همزمان تأیید نمی‌کند.

### معیار قبولی

- 010-state / sw1: تمام پنج معیار 009 دوباره برقرار باشند؛ کابل، VLAN، Trunk، سیاست مدیریت، آدرس‌ها و ارتباط چهارجهته جدا بررسی شوند. دلیل شکست: بازیابی فقط یک Fault کافی نیست؛ وضعیت هدف 009 را کامل بررسی کن.
- 010-save / sw2: Startup هر دو Switch با Running نهایی مطابق است. دلیل شکست: بعد از آخرین تعمیر هر دو Switch را ذخیره کن.
- 010-report: گزارش سه علت و تعمیر متناظر بررسی شود؛ این بخش انسانی و جدا از امتیاز خودکار مدل است.

نوع ارزیابی: live-state؛ گزارش انسانی جدا از نمرهٔ تنظیمات.

مهارت‌ها: Layered troubleshooting، Defensive access review، Minimal repair، Timed verification، Handover.

نگاشت موتور: Existing port/trunk/VTY state and dual-stack packet path.

محدودیت: گزارش علت‌ها grader خودکار ندارد؛ زمان تمام‌شده یا اجرای Show نباید قبولی جعلی بسازد.

لب‌های مرتبط برای بازاستفاده، نه معادل مستقیم: ccna-topology-017، ccna-security.
